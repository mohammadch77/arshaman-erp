# README — پروژه ERP آرشامان

> این فایل نقطه شروع هر گفتگو و session است. با یک نگاه می‌گوید پروژه کجاست، چه ساخته شده و قدم بعدی چیست.
> **بعد از هر پیشرفت مهم، بخش «وضعیت فعلی» را به‌روز کن.**

---

## پروژه در یک نگاه

سیستم ERP چندشرکتی برای **هلدینگ آرشامان**. پنج مجموعه با مدل‌های کسب‌وکار متفاوت:

| مجموعه | نوع کسب‌وکار |
|---|---|
| آرشامان | خدمات پروژه‌ای (طراحی وب، برنامه‌نویسی، سئو) |
| Verifex | ترکیبی (فیزیکی + دیجیتال) |
| Tkart | کالای فیزیکی |
| دعانو | کالای فیزیکی (محصولات مذهبی، کارت دعا هوشمند) |
| Pixentry | محصول دیجیتال |

**هدف:** یک منبع واحد حقیقت برای سود واقعی هر مجموعه + گزارش تجمیعی هلدینگ.

**مفروضات کلیدی:** مالکان جدا، تیم مالی مشترک، پرسنل مشترک، بدون تراکنش داخلی، گزارش تجمیعی لازم است.

---

## پشته فنی

- **Backend:** Laravel 11 (PHP 8.3+)
- **Frontend:** Livewire 3 + Blade
- **UI:** Mary UI (روی Tailwind + daisyUI)، RTL کامل، فونت Vazirmatn
- **Database:** MySQL 8
- **معماری:** Modular Monolith
- **روش توسعه:** vibe coding با Claude Code، فاز به فاز

## نقشه راه (هفت فاز — بازنگری‌شده به درخواست کارفرما)

> **تغییر مهم:** طبق درخواست صریح کارفرما، منابع انسانی بلافاصله بعد از هسته ساخته می‌شود
> (نه بعد از عملیات/مالی مثل نقشه اصلی سند طراحی). دلیل و پیامدهایش در `DECISIONS.md` ثبت شده.

| فاز | محتوا | وضعیت |
|---|---|---|
| ۱ | هسته (شرکت‌ها، کاربران و نقش‌ها، طرف‌حساب، ارز و تقویم) | 🔜 در حال شروع |
| ۲ | **منابع انسانی** (پرسنل، حضورغیاب، حقوق) | ⬜ برنامه‌ریزی‌شده |
| ۳ | محصولات، سفارش‌ها، انبار پایه | ⬜ برنامه‌ریزی‌شده |
| ۴ | ارسال، هزینه، بودجه — اینجا اتصال حقوق↔هزینه که در فاز ۲ به‌تعویق افتاد وصل می‌شود | ⬜ برنامه‌ریزی‌شده |
| ۵ | خدمات پروژه‌ای (تایم‌شیت، قیف فروش) | ⬜ برنامه‌ریزی‌شده |
| ۶ | حسابداری کامل (جایگزینی شایگان) | ⬜ برنامه‌ریزی‌شده |
| ۷ | CRM و گزارش تجمیعی | ⬜ برنامه‌ریزی‌شده |

**نکته:** شایگان (حسابداری) و زمان‌پرداز (حضورغیاب) API ندارند، پس ماژول‌هایشان از صفر ساخته و در نهایت جایگزین می‌شوند.

**فایده جانبی این جابه‌جایی:** طبق سند اصلی، نرخ ساعتی تایم‌شیت (فاز ۵) قرار بود اول دستی باشد و بعداً از حقوق
محاسبه شود. چون حالا HR (فاز ۲) قبل از تایم‌شیت (فاز ۵) ساخته می‌شود، از همان ابتدا نرخ واقعی از حقوق در دسترس است.

## تصمیم‌های معماری کلیدی (که نباید فراموش شوند)

1. **ثبت‌نام عمومی وجود ندارد** — فقط ادمین کل کاربر می‌سازد (الگوی دعوت‌محور).
2. **snapshot سه‌گانه:** نرخ ارز، بهای تمام‌شده، نوع تحویل — هنگام ثبت کپی می‌شوند.
3. **نوع تحویل در سطح محصول** (نه شرکت)، چون Verifex هر دو نوع را می‌فروشد.
4. **تسهیم هزینه بر پایه تایم‌شیت** (ساعت واقعی کار)، نه فرمول دلخواه.
5. **بدون تراکنش داخلی** — گزارش تجمیعی جمع ساده است، بدون elimination.
6. **همه‌چیز از تم مرکزی** — رنگ/لوگو/آیکون hardcode نمی‌شوند (قابل‌جایگزینی).
7. **RTL کامل** — هیچ صفحه‌ای چپ‌چین نیست.
8. **UUID برای همه جدول‌ها** و enum های کسب‌وکاری در سطح Laravel (نه enum دیتابیس) برای انعطاف بیشتر.
9. **نام‌گذاری صریح دیتابیس** — هر FK نقش کامل خودش را حمل می‌کند (`owner_company_id` نه `company_id`،
   `created_by_user_id` نه `created_by`). جزئیات در `DATABASE_CONVENTIONS.md`.
10. **منابع انسانی زودتر از ترتیب استاندارد** ساخته می‌شود (فاز ۲، بلافاصله بعد از هسته) — تصمیم کارفرما.

### تصمیم‌های نهایی کارفرما (نسخه ۴.۰)
- تسهیم هزینه مشترک: **به نسبت درآمد** هر شرکت (نه مساوی).
- انبار **فیزیکاً مشترک**، موجودی به تفکیک شرکت مالک.
- شرکت حمل: **تیپاکس**.
- سفارش دستی برای فروش‌های شبکه‌های اجتماعی.
- نرخ نیروی کار: **ترکیبی** (ساعتی + کارمزد قطعه‌ای طراحی).
- **سامانه مودیان** لازم است (فاز ۵).
- جایگزینی شایگان در ابتدای سال مالی؛ بررسی خواندن مستقیم از دیتابیس شایگان.
