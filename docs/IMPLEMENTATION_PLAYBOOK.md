# بخش ۰ — آماده‌سازی (قبل از اولین خط کد)

## ۰.۱. چرا این مرحله را رد نکنی

در vibe coding، کیفیت خروجی مستقیماً به کیفیت زمینه‌ای که به مدل می‌دهی وابسته است. یک روز صرف آماده‌سازی، هفته‌ها دوباره‌کاری را حذف می‌کند.

## ۰.۲. راه‌اندازی محیط

```bash
# پروژه Laravel
composer create-project laravel/laravel arshaman-erp
cd arshaman-erp

# Livewire + Mary UI (Tailwind + daisyUI به‌همراه آن راه‌اندازی می‌شود)
composer require livewire/livewire robsontenorio/mary
php artisan mary:install

# پکیج‌های پایه
composer require spatie/laravel-permission spatie/laravel-activitylog spatie/laravel-medialibrary morilog/jalali maatwebsite/excel
composer require pestphp/pest --dev
php artisan pest:install

# دیتابیس
# در .env: DB_CONNECTION=mysql, DB_DATABASE=arshaman_erp
php artisan migrate
```

## ۰.۳. فایل‌های زمینه در ریشه پروژه


**`BACKLOG.md` مهم‌تر از چیزی است که فکر می‌کنی.** بزرگ‌ترین خطر vibe coding این است که مدل (و خودت) وسط فاز ۱، هوس فیچر فاز ۴ کنید. هر ایده خوب که خارج از فاز جاری است، آنجا ثبت می‌شود و همان‌جا می‌ماند.

# بخش ۱ — ریتم کار با Claude Code

## ۱.۱. ساختار یک session سالم

هر session روی **یک Epic** کار می‌کند و این پنج گام را دارد:

| گام | کار | چرا |
|---|---|---|
| ۱ | **Plan** — اول نقشه بگیر، نه کد | با plan mode شروع کن؛ نقشه را بخوان و تأیید کن |
| ۲ | **Migration + Model + Factory** | ساختار داده اول |
| ۳ | **Test** (قبل از منطق) | برای منطق مالی الزامی |
| ۴ | **Action + Policy** | منطق کسب‌وکار در Action، نه در کامپوننت Livewire |
| ۵ | **کامپوننت Livewire + Blade view + commit** | تحویل قابل دیدن |

## ۱.۲. الگوی پرامپت مؤثر

پرامپت ضعیف:
> «ماژول سفارش رو بساز»

پرامپت خوب:
> «طبق CLAUDE.md بخش ۵، Epic 6 (سفارش‌ها) را پیاده کن.
> فقط این بخش: migration و model برای `orders` و `order_lines` با ستون‌های snapshot (exchange_rate، cost_amount، fulfillment_type).
> trait `BelongsToCompany` را اعمال کن.
> ماشین وضعیت را هنوز نساز — session بعدی.
> اول یک تست بنویس که ثابت کند سفارش شرکت الف برای کاربر شرکت ب قابل مشاهده نیست.»

**سه عنصر پرامپت خوب:** ارجاع به سند + مرز دقیق کار + تعریف «تمام».

## ۱.۳. قواعد طلایی

1. **یک ماژول در هر session.** context آلوده نشود.
2. **وقتی session طولانی شد، `/clear` بزن** و با ارجاع به CLAUDE.md شروع کن.
3. **کد مالی را خودت بخوان.** بقیه را می‌توانی سریع مرور کنی؛ محاسبه سود و سند حسابداری را خط به خط بخوان.
4. **بعد از هر Epic، بخش ۱۰ فایل CLAUDE.md را به‌روز کن.** این حافظه بلندمدت پروژه است.
5. **اگر خروجی از مسیر منحرف شد، برنگرد اصلاحش کنی — undo کن و پرامپت را دقیق‌تر بنویس.**

# بخش ۳ — فاز ۲: ارسال، هزینه‌ها، بودجه
**زمان تخمینی: ۵ تا ۷ هفته**

## Session ها

**۱. ارسال و رهگیری**
> `shipments`: order_id، carrier، tracking_code، shipped_at، delivered_at.
> هزینه ارسال به عنوان جزئی از بهای تمام‌شده سفارش ثبت شود.
> وضعیت سفارش با ثبت کد رهگیری به `shipped` برود.

**۲. هزینه‌ها**
> `expense_categories` (زیرساختی، پرسنلی، اداری، بازاریابی، تولید و تأمین، لجستیک، متغیر تراکنش) و `expenses`.
> فیلدها: owner_company_id (یا ستاد مشترک)، category_id، amount، currency، date، is_recurring، description، پیوست رسید (medialibrary).
> هزینه تکرارشونده: تولید خودکار رکورد ماهانه.

**۳. تسهیم هزینه مشترک**
> قانون تسهیم برای هزینه‌های ستادی: مساوی یا به نسبت درآمد.
> **توجه:** تسهیم هزینه پرسنل در فاز ۳ بر پایه تایم‌شیت انجام می‌شود. اینجا فقط هزینه‌های عمومی.

**۴. بودجه**
> `budgets`: owner_company_id، category_id، period (ماه شمسی)، planned_amount.
> actual_amount خودکار از expenses و orders محاسبه شود.
> گزارش انحراف.

**۵. گزارش سود و زیان**
> P&L per شرکت: درآمد − بهای تمام‌شده − هزینه عملیاتی − سهم تسهیم.
> گزارش تجمیعی: جمع ساده همه شرکت‌ها به تومان.

## خروجی فاز ۲
مدیریت می‌تواند بپرسد «این ماه هر شرکت چقدر سود داشت و کل مجموعه چقدر؟» و جواب دقیق بگیرد.

**۱. کدینگ حسابداری**
> `chart_of_accounts` چهارسطحی: گروه، کل، معین، تفصیلی.
> ابزار درون‌ریزی از اکسل برای انتقال کدینگ فعلی شایگان.

**۲. دفتر کل**
> `journal_entries` و `journal_lines`.
> **constraint سطح دیتابیس:** جمع بدهکار = جمع بستانکار.
> سند `posted` غیرقابل ویرایش؛ اصلاح فقط با reversal.

**۳. ثبت خودکار سند (Event-Driven Posting)**
> هر رویداد سند بسازد: فروش، خرید، هزینه، پرداخت، حقوق.
> **تست حیاتی:** پس از ۱۰۰ تراکنش تصادفی، تراز کل صفر باشد.

**۴. فاکتور و پرداخت**
> `invoices` با ماشین وضعیت، `payments` با نرخ ارز snapshot.

**۵. خرید و تدارکات**
> سفارش خرید → رسید کالا (به‌روزرسانی انبار) → تطبیق فاکتور تأمین‌کننده.

**۶. بستن دوره مالی**
> تراز آزمایشی، بستن سال، انتقال مانده‌ها.

## توصیه اجرایی حیاتی
جایگزینی شایگان را **در ابتدای سال مالی** انجام بده و **یک دوره موازی** اجرا کن: هم در شایگان ثبت شود هم در سامانه، و اعداد را مقایسه کن. تا وقتی دو سیستم یکی نشدند، شایگان را کنار نگذار.
